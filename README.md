# CI/CD Pipeline for a PHP Application

## Overview

This project implements a Continuous Integration and Continuous Deployment (CI/CD) pipeline using Jenkins and Docker to automate the build, containerization, and deployment of a PHP web application.

The pipeline retrieves source code from GitHub, builds a Docker image, pushes the image to Docker Hub, and supports automated deployment to a running environment. It also includes a deployment approval stage and configurable deployment options.

## Technologies Used

- **Jenkins** — CI/CD pipeline automation
- **Git & GitHub** — Source code management
- **Docker** — Application containerization
- **Docker Hub** — Container image registry
- **Kubernetes** — Container orchestration and deployment
- **PHP & Apache** — Application runtime
- **Jenkinsfile** — Pipeline definition as code

## Pipeline Workflow

1. **Source Code Checkout:** Jenkins retrieves the application source code from the GitHub repository's `main` branch.
2. **Build and Push:** Jenkins builds a Docker image and pushes it to Docker Hub using stored credentials.
3. **Deployment Approval:** An optional manual approval stage allows deployment to be reviewed before proceeding.
4. **Docker Deployment:** The application can be deployed as a Docker container with the configured host port mapped to the container's HTTP port.
5. **Kubernetes Deployment:** The pipeline can also support Kubernetes deployment using the project's Kubernetes manifests.

## Prerequisites

- Jenkins installed and configured
- Git installed and access to the GitHub repository
- Docker installed on the Jenkins agent
- Docker Hub account
- PHP application source code
- A Kubernetes cluster and `kubectl` configured if using Kubernetes deployment

## Configuration

### Jenkins Credentials

Configure the following credentials in Jenkins before running the pipeline:

| Credential ID | Purpose |
|---|---|
| `github_cred` | GitHub repository authentication, if required |
| `dockerhub_cred` | Docker Hub authentication |

Store credentials securely in Jenkins rather than hardcoding usernames, passwords, or access tokens in the `Jenkinsfile`.

### Docker Image

The pipeline builds and publishes the application image using a build-specific tag:

```text
abdelrhman11/my_php_app:${BUILD_NUMBER}
```

Using `BUILD_NUMBER` helps distinguish images produced by different pipeline runs.

## Running the Pipeline

1. Configure the Jenkins credentials.
2. Create a Jenkins Pipeline job.
3. Configure the job to retrieve the `Jenkinsfile` from source control.
4. Provide the GitHub repository URL and select the `main` branch.
5. Ensure the Jenkins agent has Docker access.
6. Run the pipeline and monitor the stages in the Jenkins console output.
7. Approve deployment when prompted, if the approval stage is enabled.

## Deployment

### Docker

The application can be run as a container with port `9090` on the host mapped to port `80` inside the container.

Example:

```bash
docker run -d \
  -p 9090:80 \
  abdelrhman11/my_php_app:<BUILD_NUMBER>
```

Replace `<BUILD_NUMBER>` with the tag generated by a successful pipeline run.

Access the application at:

```text
http://localhost:9090
```

If Jenkins deploys to a remote server, use that server's address instead of `localhost`.

### Kubernetes

For Kubernetes deployment, the pipeline can apply the project's manifests to a configured cluster.

Example commands:

```bash
kubectl apply -f k8s/deployment.yml
kubectl apply -f k8s/service.yml
```

Ensure the manifests reference the intended Docker image tag and that the Jenkins agent has the required Kubernetes access.
